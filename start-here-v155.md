# The Local v155 · Venue-based Virtual Pub Tables

1. Use the Netlify staging site and its matching Supabase project. Back up the staging database first. The v155 migration requires the secure table, v123 table extensions and venue directory schemas already in use by The Local.
2. Run `INSTALL-V155-PUB-TABLES.sql` in Supabase SQL Editor, then deploy this build to staging. Before enabling the feature in production, apply the same migration to the production project and deploy the site together. This version replaces the old table creation and invitation calls with venue-aware calls, so older builds no longer create or join by the old API after migration.
3. Ensure each selectable venue, including Coombe if in use, has an approved or featured row in the database venue directory. A display-only fallback venue card is not a directory row. The existing Coombe registration SQL is included in the package.
4. Open **Virtual Pub Tables**, select a venue, then select **Pull up a chair**. Owners can open **Set up a new table**. Invited members select the venue named by the inviter, open **Join with an invitation**, and enter the code. Other visitors can ask a moderator to approve a seat.
5. An owner can pair an older table with the chosen venue under **Place my existing tables**. The migration preserves its members, messages, events and other records. Review each placement before confirming since a placed table stays tied to that venue.
6. With two test accounts, check table creation, request approval, a correct and incorrect invitation venue, message updates, sending a voice note on a microphone-enabled phone, attaching media, moderator removal, and mobile layout. Audio recording requires HTTPS and browser microphone permission. The chat searches the latest 80 messages. It updates periodically while visible, and the seat labels show approved members, rather than presence.

The pub photograph is the existing Virtual Pub Tables image. Seat labels come from approved members of the selected table. Chat uses Supabase membership controls and signed links for attachments. WhatsApp-compatible end-to-end encryption, calls, and full feature parity are outside this build.
